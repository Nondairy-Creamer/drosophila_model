# Project Notes

## Figures

Preserve the existing figure-output structure going forward:

- General figures (not tied to a specific trained model) go in the repo-root
  `figures/` folder, in a subfolder named after the analysis/script that
  produced them: `figures/<analysis_name>/<figure_name>` (e.g.
  `figures/stimulus_flow/`, `figures/two_eyes/`).
- Figures generated by running a model go inside that model's folder, under a
  `figures/` subfolder keyed by analysis name:
  `models/<model_name>/figures/<analysis_name>/<figure_name>` (e.g.
  `models/30hz_best_conductance/figures/sine_wave_sweep/`).

Never write figures to the repo root or an analysis directory directly; always
nest them under the analysis-name subfolder as above.

### Layout

- `<data_folder>/config.toml` — a copy of run config lives here too
- `<data_folder>/connectome_data/` — connectome (`baked/cell_info.parquet`, `baked/synapses.parquet`)
- `<data_folder>/stimulus/raw/` — raw stimulus source files. The large raw
 inputs — the drone rigs `drone_videos/` + `drone_poses/` (small_drone) and
 `rpi_drone/` (rpi_drone, with `rpi_drone/dome_calib/`), and the raw
 `panoramic/*.mat` panoramas — are read once by `process_raw_data.py`. Also
 here: `fib_forest_fly_view_dataset_fwd.pkl` (raw rendered fly-view source).
- `<data_folder>/stimulus/baked/` — caches produced by
 `drosophila_model/data_handling/process_raw_data.py <raw_type>`
 (`small_drone`, `rpi_drone`, `random_pano`, `flyview`) and consumed by the
 on-the-fly generators in `stimulus_generators.py`: `small_drone.pt`,
 `rpi_drone.pt` (ommatidium-sampled clips at native fps), `all_panoramic.pt`
 (consolidated raw panorama images), and `flyview.pt` (flow +
 depth-based odometry baked from `fib_forest_fly_view_dataset_fwd.pkl`, float32,
 no depth).
- `<data_folder>/stimulus/training/` — fixed, training-ready datasets produced by
 `drosophila_model/data_handling/create_training_data.py <stimulus_type>`,
 one `<stimulus_type>.pt` per type (e.g. `small_drone.pt`, `rpi_drone.pt`).
 Training loads these via `training_utilities.load_processed_stimulus` (no
 on-the-fly generation).
